# 从零搭多传感器融合系统

> 一份面向工程师的实操指南：从传感器模型、时空对齐、外参标定、数据调度，到因子图构建、融合架构选型、退化检测与故障切换，手把手教你搭一套可运行的多传感器融合 SLAM 系统。使用 C++17 + ROS 2 + GTSAM/Ceres 技术栈。

## 0. 前置知识

搭建多传感器融合系统之前，需要先建立对"传感器在说什么"和"这些数据在哪个坐标系里"的清晰认知。

### 0.1 传感器模型

每个传感器有自己独特的数据格式、噪声特性和失效模式：

| 传感器 | 典型频率 | 测量量 | 主要噪声源 | 失效场景 |
|--------|---------|--------|-----------|---------|
| **IMU** (加速度计+陀螺仪) | 100-400 Hz | 加速度 (m/s²)、角速度 (rad/s) | 白噪声、随机游走偏置、比例因子误差 | 强振动饱和、高 g 机动 |
| **LiDAR** (机械/固态) | 5-20 Hz | 3D 点云 (x,y,z,intensity,time) | 测距噪声、运动畸变、多径反射 | 雨雾雪、镜面反射、无结构环境 |
| **单目相机** | 20-60 Hz | 2D 图像 (灰度/RGB) | 光子噪声、读出噪声、曝光变化 | 过暗/过亮、无纹理、动态模糊 |
| **双目相机** | 20-60 Hz | 左右 2D 图像对 | 同单目 + 基线校准误差 | 同单目 |
| **GNSS 接收机** | 1-10 Hz | WGS84 经纬高 + 速度 | 多径、电离层延迟、钟差 | 城市峡谷、隧道、室内 |
| **轮速计** | 50-100 Hz | 轮速 (m/s)、转向角 | 滑移、轮胎形变、胎压变化 | 打滑、越野、悬空 |

**关键认知**：IMU 是唯一能在传感器失效期间维持位姿传播的高频传感器，是所有融合系统的"骨架"。其他传感器提供绝对或相对约束，修正 IMU 累积的漂移。

参考页面：[[传感器-传感器标定]]、[[传感器-IMU预处理]]、[[传感器-事件相机]]、[[概念-IMU预积分]]

### 0.2 时空坐标系

多传感器系统中坐标系管理是"地基"——错一个符号，后面全盘皆错。

**核心坐标系**（详见 [[架构-坐标系管理]]）：

```
世界系 (World / ENU / Map)
    │
    ├── T_wb: IMU body → World (这是 SLAM 估计的核心状态)
    │       │
    │       ├── T_bc: Camera → Body (外参, 也叫 T_imu_cam)
    │       ├── T_bl: LiDAR → Body
    │       ├── T_bg: GNSS 天线 → Body (杆臂/lever arm)
    │       └── T_bo: Odometry → Body
    │
    └── T_w_ecef: WGS84 → ENU (经纬高→笛卡尔, 以初始点为原点)
```

**变换链举例**：一个 LiDAR 点 p_lidar 要投影到世界坐标系：

```
p_world = T_wb * T_bl * p_lidar
```

**IMU 本体坐标系约定**（参照 ROS REP-103 和 REP-105）：
- x 轴向前，y 轴向左，z 轴向上 (FLU, ENU)
- 旋转使用 Hamilton 四元数顺序 (w, x, y, z)

**单位约定**：
- 时间戳：统一为纳秒 (uint64_t) 或 ROS `Time`
- 平移：米 (m)
- 角度：弧度 (rad)
- IMU 加速度：m/s²，角速度：rad/s

### 0.3 数学预备

涉及 [[数学-SE3指数映射]] 和 [[数学-流形优化]]。核心概念：

- 旋转使用 SO(3) 李群，局部扰动用 so(3) 李代数（3 维），指数映射 `Exp(δθ) = exp([δθ]×)` 做局部参数化
- 位姿 SE(3) 局部参数化用 6 维向量 (δθ, δt)
- 非线性优化中，状态更新公式为 `x_new = x ⊕ δx`，其中 `⊕` 是 retraction 操作
- 因子图求解需要使用 Lie 群上的导数（右雅可比或左雅可比）

```pseudo
# SO(3) 右扰动 Jacobian 模板
def jacobian_wrt_rotation(R, point):
    """误差 e = f(R) 对旋转的 Jacobian (右扰动)"""
    # de/dδθ = de/d(R*point) * d(R*Exp(δθ)*point)/dδθ | δθ=0
    # d(R*Exp(δθ)*p)/dδθ = -R * skew(p)  (一阶近似)
    J_point = compute_jacobian_wrt_3d_point()
    return -J_point * R * skew(point)
```

## 1. 时间同步

多传感器融合系统最隐蔽的 bug 来源：时间戳没对齐。不同传感器的采样时刻、传输延迟、时钟漂移各有不同，必须显式处理。

### 1.1 问题的本质

实际系统中相机和 IMU 通常是两个独立的硬件时钟：
- 相机：由图像传感器像素时钟驱动，曝光时刻在硬件寄存器中
- IMU：由 MEMS 传感器 ADC 采样时钟驱动
- ROS 驱动层：数据到达 CPU 的时间（`header.stamp`）可能不是真实采集时刻

时间关系可建模为：

```
t_camera = t_imu + t_d
```

其中 `t_d` 是 IMU 相对于相机的时间偏移（典型值 ±5-50 ms）。若 `t_d` 不准确，高速运动时视觉观测会错误地关联到错误的 IMU 状态，导致系统性偏差。

详见 [[方法-IMU-camera时间偏移估计]]。

### 1.2 硬件同步 vs 软件对齐

| 方案 | 精度 | 成本 | 适用场景 |
|------|------|------|---------|
| **硬件 PTP (IEEE 1588)** | μs 级 | 需要支持 PTP 的硬件和交换机 | 自动驾驶量产系统 |
| **外部触发线 (sync cable)** | <1 μs | 需要传感器支持 sync-in/out | 科研平台、LiDAR+相机硬同步 |
| **GPS PPS 脉冲** | <1 μs | 需要 GNSS 接收机输出 PPS | 室外系统、多车协同 |
| **软件 NTP/chrony** | ms 级 | 零成本 | 开发调试、低动态场景 |
| **在线 td 估计** | ms 级（依赖运动激励） | 零硬件成本 | VIO 系统的兜底方案 |

**工程建议**：硬件同步是首选（`t_d` 固定为线缆延迟），软件 td 估计作为在线兜底。VINS-Fusion 在 `ESTIMATE_TD=1` 时在线估计 `t_d`，但仅当 `Vs[0].norm() > 0.2 m/s`（有充分运动激励）时才激活优化。

### 1.3 伪代码：时间偏移在线估计

```pseudo
function estimate_time_offset(imu_queue, camera_queue, features, velocities):
    td = config.td_initial  # 初值，优先从硬件同步获得
    
    for each camera_frame:
        # 1. 按 td 修正 IMU 时间戳
        imu_start_time = camera_frame.time + td
        imu_end_time = camera_frame.time + td
        
        # 2. IMU 预积分（用修正后的时间）
        preint = imu_preintegrator.integrate(
            get_imu_segment(imu_start_time, imu_end_time)
        )
        
        # 3. 时间补偿特征点坐标
        for each tracked_feature:
            pts_i_td = pts_i - (td_param - td_observed) * velocity_i / focal_length
            
        # 4. 构建因子图
        problem.add_parameter_block(td_param, dim=1)
        if velocity_norm < 0.2:  # 可观测性守卫
            problem.set_parameter_block_constant(td_param)
        
        for each frame_pair:
            problem.add_residual(IMUFactor(preint))
            problem.add_residual(ProjectionTdFactor(pts_i_td, pts_j_td, ...))
        
        problem.solve()
        td = td_param[0]  # 更新 td 估计
```

### 1.4 LiDAR-IMU 时间同步

LiDAR-IMU 系统通常不显式估计时间偏移，而是依赖：

- **点云逐点时间戳**：机械式 LiDAR（如 Velodyne）每个点有相对于扫描起始的 `time` 字段，用于去畸变（deskew）
- **预积分时间对齐**：LIO-SAM 在 `imuPreintegration.cpp` 中以 `currentCorrectionTime - delta_t` 作为 IMU 积分截至时刻
- **硬同步方案**：通过 PPS 信号同时触发 LiDAR 和 IMU，确保时间戳一致性

参考页面：[[方法-IMU deskew]]、[[IMU数据管线]]、[[LiDAR数据管线]]

## 2. 外参标定

外参标定决定了不同传感器观测能否转换到同一个坐标系。差一个度，融合就变成"污染"。

### 2.1 标定对象与重要性

| 外参对 | 标定内容 | 对融合的影响 |
|--------|----------|-------------|
| IMU ↔ 相机 | 6-DOF 变换 + 时间偏移 | 影响所有视觉特征重投影，直接影响 VIO 精度 |
| IMU ↔ LiDAR | 6-DOF 变换 | 影响点云去畸变和 scan matching 初值 |
| IMU ↔ GNSS 天线 | 3-DOF 平移 (杆臂) | 旋转时未补偿杆臂会产生米级位置误差 |
| 相机 ↔ LiDAR | 6-DOF 变换 | 影响 LiDAR-视觉融合（着色、深度关联） |
| 双目左↔右 | 6-DOF 变换 | 影响三角化深度精度 |

详见 [[传感器-传感器标定]]、[[方法-多传感器外参在线标定]]。

### 2.2 手眼标定：旋转外参的初始估计

相机-IMU 旋转外参可以通过"手眼标定"从传感器运动序列中求解。核心方程：

```
R_{c_k}^{c_{k+1}} · R_{cb} = R_{cb} · R_{b_k}^{b_{k+1}}
```

其中 `R_{c_k}^{c_{k+1}}` 来自视觉相对旋转（本质矩阵分解），`R_{b_k}^{b_{k+1}}` 来自 IMU 预积分旋转。汇集多帧约束，构造四元数形式的超定线性系统 `A q_cb ≈ 0`，通过 SVD 求解。

```pseudo
function hand_eye_calibration(Rc_list, Rb_list, angular_threshold=5.0):
    A = zeros(len(Rc_list) * 4, 4)
    for i in range(len(Rc_list)):
        q_c = quat(Rc_list[i])    # 视觉相对旋转
        q_b = quat(Rb_list[i])    # IMU 预积分旋转
        
        # Huber 权重抑制异常帧
        ang_dist = angular_distance(q_c, q_b)
        huber = 5.0 / ang_dist if ang_dist > 5.0 else 1.0
        
        # 四元数左乘/右乘矩阵
        L = quat_left_mult_matrix(q_c)
        R_mat = quat_right_mult_matrix(q_b)
        A[i*4:(i+1)*4, :] = huber * (L - R_mat)
    
    U, S, Vt = svd(A)
    q_cb = Vt[3, :]       # 最小奇异值对应向量 (R_cb)
    ric = quat_to_R(q_cb).T   # 取逆得 R_imu_cam
    return ric
```

参考实现：`raw/codes/VINS-Fusion/vins_estimator/src/initial/initial_ex_rotation.cpp:L29-L66`

**注意**：手眼标定只能估计旋转分量，平移初值需要物理测量或 Kalibr 离线标定提供。

### 2.3 三种工作模式

VINS-Fusion 通过 `ESTIMATE_EXTRINSIC` 参数定义三种模式（详见 [[传感器-传感器标定]]）：

| 模式 | ESTIMATE_EXTRINSIC | 行为 | 适用场景 |
|------|-------------------|------|---------|
| **固定** | 0 | 外参完全固定，使用出厂标定值 | 传感器刚性安装、温度稳定 |
| **精化** | 1 | 滑动窗口中微调外参（从初值出发） | 在线运行，适应温度漂移 |
| **自标定** | 2 | 无初值时全自动标定（手眼标定+精化） | 快速部署、传感器重新安装 |

### 2.4 在线精化的可观测性

外参优化需要**运动激励**才能可观。VINS-Fusion 使用 `Vs[0].norm() > 0.2 m/s` 作为守卫条件：

| 运动类型 | 旋转可观 | 平移可观 |
|----------|----------|----------|
| 纯平移 | 部分 (yaw/pitch) | 是 |
| 纯旋转 | 是 | 否 |
| 6-DOF 一般运动 | 是 | 是 |
| 静止 | 否 | 否 |

**工程陷阱**：外参平移与尺度在单目 VIO 中耦合。若尺度初始化错误，`t_bc` 会吸收误差。

```pseudo
        # ---- 阶段 1+2: 手眼标定 ----
```

## 3. 传感器调度

传感器数据以不同频率、不同延迟到达，调度层的任务是：把杂乱的异步数据流组织成估计器可以消费的"测量窗口"。

### 3.1 问题定义

调度层要解决的核心问题（详见 [[架构-Pipeline 传感器数据调度]]）：

1. **多频率对齐**：IMU 200Hz, LiDAR 10Hz, 相机 30Hz, GNSS 1Hz——哪种触发机制？
2. **数据关联**：哪些 IMU 测量属于当前 LiDAR 帧的时间窗口？
3. **乱序到达**：ROS 消息可能后发先至，如何处理？
4. **背压管理**：后端处理慢于前端时，队列如何裁旧？

### 3.2 三种调度模式

| 模式 | 代表实现 | 做法 | 风险 |
|------|---------|------|------|
| **多队列缓存** | slam_fusion_core | IMU/GNSS/Visual 各自 `std::deque`，`runStep()` 驱动后端 | 后端无法访问实际数据 |
| **时间戳有序容器** | fusions_slam `MeasureGroupAdd` | `std::map<uint64_t, DataUnit>` 按纳秒时间戳自动排序 | 类型分发复杂 |
| **帧驱动窗口** | LIO-SAM, VINS-Fusion | 以 LiDAR/相机帧为触发，收集时间范围内的 IMU | 边界插值易出错 |

### 3.3 推荐实现：时间排序缓冲 (MeasureGroupAdd)

fusions_slam 的 `MeasureGroupAdd` 是一个干净的设计（`raw/codes/fusions_slam/include/fusion_slam/type/measure_group.h`）：

```cpp
struct DataUnit {
    int type;        // 0:IMU  1:LiDAR  2:GNSS  3:Camera  4:Speed
    ImuType imu;
    PointCloud cloud;
    Pose rtkPose;
};

struct MeasureGroupAdd {
    uint64_t lidarBeginTime;
    std::map<uint64_t, DataUnit> mapDatas;   // 纳秒 → 数据，天然有序
    uint64_t lidarEndTime;
};
```

**设计要点**：
- 所有传感器数据统一为 `DataUnit`，通过 `std::map` 自动按时间排序
- 以 LiDAR 帧起止时间定义测量窗口边界
- `DataUnit.type` 支持未来扩展新传感器

### 3.4 线程模型

多传感器融合系统至少需要以下线程（参考 [[架构-多传感器融合架构]] 和 phad_fusion 设计）：

```pseudo
# 四线程架构
┌──────────────────────────────────────────────────┐
│  线程 1: 前端线程 (Frontend)                       │
│  ├─ ROS subscriber 回调 (IMU/LiDAR/Camera/GNSS)   │
│  ├─ 传感器预处理 (去畸变、特征提取、积分)            │
│  ├─ 生成因子/残差                                  │
│  └─ 推入 lock-free 队列 → 线程 2                  │
├──────────────────────────────────────────────────┤
│  线程 2: 优化线程 (Backend)                        │
│  ├─ 消费前端队列中的因子                           │
│  ├─ iSAM2 增量更新 / 滑动窗口优化                   │
│  ├─ 周期性重线性化                                 │
│  └─ 发布优化后状态 (原子指针) → 线程 4             │
├──────────────────────────────────────────────────┤
│  线程 3: 回环线程 (Loop Closure)                   │
│  ├─ 关键帧数据库维护                               │
│  ├─ 候选检索 → 几何验证 → 回环因子生成             │
│  └─ 验证通过的回环因子 → 线程 2 的因子队列          │
├──────────────────────────────────────────────────┤
│  线程 4: 可视化/输出线程 (Output)                  │
│  ├─ TF 发布 (map→odom→base_link)                  │
│  ├─ 点云/轨迹/因子图状态 Rviz 可视化                │
│  └─ 读取线程 2 的原子快照，无锁                    │
└──────────────────────────────────────────────────┘
```

**线程间同步原则**：
- 前端→优化：lock-free SPSC 队列（如 `boost::lockfree::spsc_queue`）
- 优化→可视化：`std::atomic<StateSnapshot*>` 原子指针交换
- 回环→优化：因子写入队列（与前端因子同一队列，保证时序）

### 3.5 伪代码：调度层

```pseudo
class SensorScheduler:
    def __init__(self):
        self.measure_buffer = map<uint64_t, DataUnit>  # 纳秒 → 数据
        self.imu_queue = deque<ImuData>()
        self.frontend_queue = LockFreeQueue<Factor>()
    
    def on_imu(imu_msg):
        data_unit = DataUnit(type=IMU, imu=parse_imu(imu_msg))
        self.measure_buffer[imu_msg.timestamp_ns] = data_unit
    
    def on_lidar(lidar_msg):
        lidar_begin = lidar_msg.timestamp_ns - lidar_msg.scan_time_ns / 2
        lidar_end = lidar_msg.timestamp_ns + lidar_msg.scan_time_ns / 2
        
        # 提取窗口内的 IMU 数据
        window = self.measure_buffer.range(lidar_begin, lidar_end)
        imus_in_window = [d for d in window if d.type == IMU]
        
        if len(imus_in_window) < MIN_IMU_COUNT:
            return  # 窗口不完整，跳过
        
        # 生成因子
        factors = self.process_scan(lidar_msg, imus_in_window)
        for f in factors:
            self.frontend_queue.push(f)
        
        # 清理旧数据
        self.measure_buffer.erase_before(lidar_begin - WINDOW_MARGIN)
```

## 4. 因子图构建

"Everything is a Factor"——将每种传感器观测建模为因子图中独立的因子，是实现可插拔多传感器融合的核心思想。

### 4.1 为什么是因子图

详见 [[概念-因子图]] 和 [[GTSAM 因子图工作流]]。因子图相比 EKF/矩阵形式的优势：

| 考量 | EKF/IESKF | 因子图 (GTSAM/Ceres) |
|------|-----------|---------------------|
| 传感器建模 | 需逐一推导耦合 Jacobian，新传感器改写量大 | 每个传感器独立因子，即插即用 |
| 线性化质量 | 单次线性化，线性化点固定后不可逆 | 迭代优化 + iSAM2 选择性重线性化 |
| 精度 | 累积漂移 | 接近批量 BA |
| 不确定性 | 协方差实时可用 | GTSAM 自动协方差恢复 |

### 4.2 因子类型速查表

在一个完整的 LiDAR-IMU-Visual-GNSS 融合系统中，你会创建以下因子：

| 因子类型 | 传感器 | 约束形式 | 频率 | GTSAM 类 / Ceres 实现 |
|----------|--------|---------|------|----------------------|
| **IMU 预积分** | IMU | 两帧间相对运动 (位置/速度/姿态) | 100-200Hz 积分, 每关键帧一个因子 | `CombinedImuFactor` / `ImuFactor` |
| **IMU bias 游走** | IMU | bias 随机游走先验 | 每关键帧 | `BetweenFactor<imuBias::ConstantBias>` |
| **LiDAR ICP** | LiDAR | 点到面/点到线/点到分布匹配 | 10 Hz | 自定义 IcpFactor (Ceres) / `BetweenFactor<Pose3>` 封装 |
| **视觉重投影** | 相机 | 2D 特征重投影误差 | 30 Hz | `SmartProjectionPose3Factor` (GTSAM) / `ProjectionFactor` (Ceres) |
| **立体视觉** | 双目相机 | 左右目特征匹配约束 | 30 Hz | `GenericStereoFactor` (GTSAM) |
| **GNSS 位置** | GNSS | 3-DOF 位置先验 | 1-10 Hz | `PriorFactor<Pose3>` (GTSAM) |
| **GNSS 速度** | GNSS | 3-DOF 速度先验 | 1-10 Hz | `PriorFactor<Vector3>` (GTSAM) |
| **轮速计** | 轮速编码器 | 帧间平移约束 | 50 Hz | `BetweenFactor<Pose3>` (预积分封装) |
| **回环闭合** | 任意 | 非连续帧间位姿约束 | 按需 | `BetweenFactor<Pose3>` |
| **零速更新 (ZUPT)** | IMU | 速度为 0 的先验 | 静止检测触发 | `PriorFactor<Vector3>` |
| **外参先验** | — | 外参软约束 | 固定 | `PriorFactor<Pose3>` (弱协方差) |
| **匀速运动先验** | — | 帧间位姿平滑约束 | 每帧 | `BetweenFactor<Pose3>` |

### 4.3 GTSAM vs Ceres 选择

详见 [[优化后端选型指南]] 和 [[组件-GTSAM]]、[[组件-Ceres-Solver]]。

| 维度 | GTSAM | Ceres |
|------|-------|-------|
| **因子图原生支持** | 是 (`NonlinearFactorGraph` + `ISAM2`) | 否，需手写 Problem 构建 |
| **增量优化** | `ISAM2` 原生支持在线增量更新 | 需手动实现边缘化 |
| **自动求导** | 有限（需派生 `NoiseModelFactor`） | 完整支持 AutoDiff |
| **解析 Jacobian** | Jacobian 矩阵约定清晰 | `CostFunction::Evaluate` 返回 Jacobian |
| **预积分内置** | 是（`PreintegratedImuMeasurements`） | 需自实现 |
| **社区与文档** | 学术导向，文档偏理论 | 工程导向，Google 维护 |
| **与 ROS 集成** | 需自行适配 | 已有多种 VIO/LIO 工程参考 |
| **国内工程使用** | LIO-SAM, FAST-LIO 系 | VINS-Fusion, ORB-SLAM3, IC-GVINS |

**选型建议**：
- 从零搭建 → **GTSAM iSAM2**，因子图建模简洁，增量优化天然实时
- 已有滑动窗口/边缘化需求 → **Ceres**，配合自定义边缘化逻辑，灵活度更高
- 混合方案（推荐）→ 前端用 IESKF (Eigen 自实现)，回环用 GTSAM 全局 PGO，如 [[算法-fusions_slam]]

```pseudo
# --- GTSAM 方式 ---
def build_and_optimize_gtam():
    graph = NonlinearFactorGraph()
    values = Values()
    
    # 1. 先验因子（锚定首个位姿）
    prior_noise = noiseModel.Diagonal.Sigmas([0.01]*3 + [0.1]*3)
    graph.add(PriorFactor_Pose3(X(0), initial_pose, prior_noise))
    values.insert(X(0), initial_pose)
    
    # 2. IMU 预积分因子
    for key in 1..N:
        preint = imu_preintegrator.integrate(imus_between_frames)
        imu_noise = noiseModel.Gaussian.SqrtInformation(
            preint.preintMeasCov().inverse())
        graph.add(CombinedImuFactor(
            X(key-1), V(key-1), X(key), V(key), B(key-1), B(key), preint))
        graph.add(BetweenFactor_imuBias(
            B(key-1), B(key), ConstantBias(),
            noiseModel.Diagonal.Sigmas(sqrt(preint.deltaTij()) * bias_noise)))
        
        # 预测初值
        predicted = preint.predict(prev_state, prev_bias)
        values.insert(X(key), predicted.pose())
        values.insert(V(key), predicted.velocity())
    
    # 3. LiDAR ICP 因子
    lidar_noise = noiseModel.Isotropic.Sigma(6, 0.1)
    for each scan_match:
        T_lidar_rel = icp.match(source, target)
        graph.add(BetweenFactor_Pose3(X(i), X(j), T_lidar_rel, lidar_noise))
    
    # 4. 视觉因子（SmartFactor 自动管理 landmark）
    for each tracked_feature:
        graph.add(SmartProjectionPose3Factor(cam_noise, K))
        # 为每个观测帧添加投影
        factor.add(camera_pose, landmark_id, uv_measurement)
    
    # 5. GNSS 先验因子
    gnss_noise = noiseModel.Diagonal.Sigmas([
        xy_std, xy_std, z_std,  # 水平精度 > 垂直精度
        100, 100, 100])          # 无姿态约束
    for each gnss_fix:
        T_world_gnss = wgs84_to_enu(gnss_msg) * T_bg  # 补偿杆臂
        graph.add(PriorFactor_Pose3(X(key), T_world_gnss, gnss_noise))
    
    # 6. 增量求解
    isam2 = ISAM2(ISAM2Params())
    isam2.update(graph, values)
    result = isam2.calculateEstimate()
    return result

# --- Ceres 方式 ---
def build_and_optimize_ceres():
    problem = Problem()
    
    # 外参参数块
    problem.AddParameterBlock(ex_pose, 7, 
        new PoseLocalParameterization())  # SE(3) 局部参数化
    if velocity_norm < 0.2:
        problem.SetParameterBlockConstant(ex_pose)
    
    # 时间偏移参数块
    problem.AddParameterBlock(td, 1)
    if velocity_norm < 0.2:
        problem.SetParameterBlockConstant(td)
    
    # 添加视觉 + IMU 残差块
    for each frame_pair:
        ceres::CostFunction* imu_cost = new IMUFactor(preint)
        problem.AddResidualBlock(imu_cost, loss, pose_i, vel_i, bias_i,
                                  pose_j, vel_j, bias_j)
    
    for each feature_obs:
        ceres::CostFunction* proj_cost = new ProjectionTdFactor(
            pts_i, pts_j, vel_i, vel_j, td_i, td_j)
        problem.AddResidualBlock(proj_cost, loss,
            pose_i, pose_j, ex_pose, inv_depth, td)
    
    Solver::Options options;
    options.linear_solver_type = DENSE_SCHUR;
    Solver::Summary summary;
    Solve(options, &problem, &summary);
```

### 4.5 因子权重自适应

不同环境下各传感器可靠性不同，因子权重应动态调整：

```pseudo
def adaptive_factor_weight(sensor_type, diagnostics):
    if sensor_type == LIDAR:
        # 结构化场景权重高，退化时降低
        degenerate_dims = check_degeneracy(hessian)
        weight = 1.0 / (1.0 + len(degenerate_dims) * 0.5)
    elif sensor_type == VISUAL:
        # 特征跟踪数量决定权重
        n_features = len(tracked_points)
        weight = min(1.0, n_features / MIN_GOOD_FEATURES)
    elif sensor_type == GNSS:
        # HDOP 决定信任程度
        weight = 1.0 / (1.0 + hdop)
    else:
        weight = 1.0
    return weight
```

## 5. 融合架构

### 5.1 松耦合 vs 紧耦合

这是多传感器融合系统最关键的架构决策。

| 维度 | 松耦合 | 紧耦合 |
|------|--------|--------|
| **数据流** | 各子系统独立输出位姿，再做位姿级融合 | 所有原始观测进入同一优化器/滤波器 |
| **协方差** | 无统一协方差，信息可能重复/丢失 | 统一协方差，统计一致性最优 |
| **工程复杂度** | 低——子系统可独立开发调试 | 高——需统一状态定义、时间戳、外参 |
| **降级能力** | 天然支持（子系统挂了不影响其他） | 需内部检测+退化方向投影 |
| **精度上限** | 中等（协方差不一致导致次优） | 最高（全信息联合优化） |
| **代表工程** | LVI-SAM, VINS-Fusion+GPS | FAST-LIVO2, R3LIVE, ORB-SLAM3 VIS |

**LVI-SAM 松耦合案例**（详见 [[架构-多传感器松耦合]]、[[方法-LVI-SAM互补架构]]）：

- 5 个独立 ROS 节点：imageProjection, featureExtraction, imuPreintegration, mapOptimization, visual_odometry
- VIS→LIS：VINS 位姿增量用作 LiDAR scan-to-map 初始猜测
- LIS→VIS：LiDAR 优化的 bias/gravity 通过 `odometry/imu` 消息传给 VINS
- 两个独立优化器：GTSAM ISAM2 (LIS) + Ceres 滑动窗口 (VIS)

### 5.2 紧耦合架构：双 ESIKF vs 统一 IESKF vs 统一因子图

详见 [[架构-双ESIKF架构]]、[[方法-统一IESKF融合]]。

| 架构 | 代表 | 状态维度 | 特点 |
|------|------|---------|------|
| **双 ESIKF** | R3LIVE | LIO: 18维, VIO: 29+维 | 模块化，独立调试，协方差不一致 |
| **统一 IESKF** | FAST-LIVO2 | 30维 (位姿+速度+bias+外参+td+辐照参数) | 单一协方差，理论最优，实现复杂 |
| **统一因子图** | phad_fusion 设计 | 不限 | 可插拔传感器，iSAM2 增量优化 |

**FAST-LIVO2 的优势**：将所有 LiDAR、视觉和 IMU 残差统一在一个 IESKF 框架中处理，避免了双 ESIKF 的信息重复问题。代价是 Jacobian 推导复杂，添加新传感器需要修改滤波器核心。

### 5.3 双系统冗余设计

在实际工程中，最可靠的方案往往是"一套 LIO + 一套 VIO = 双保险"：

```pseudo
┌──────────────────────────────────┐
│          LIO 子系统               │
│  LiDAR → deskew → ICP → ESIKF  │
│           ↓ 位姿                  │
│      融合裁决器 ← VIO 位姿 ←     │
│           ↓        ↑              │
│       最终输出    交叉监控         │
│           ↑        ↓              │
│          VIO 子系统               │
│  Camera → KLT → 重投影 → iSAM2  │
└──────────────────────────────────┘
```

**裁决逻辑**：
1. 两者正常 → 取 LIO 位姿为主要输出（几何精度更高），VIO 用于回环和重定位
2. LIO 退化 → 降级到 VIO 输出 (LIO-as-Prior 模式，详见 [[架构-LIO-as-Prior设计]])
3. VIO 失效 → LIO 独立跟踪，视觉模块等待重新初始化
4. 两者失效 → IMU 单独传播（短暂维持 < 2-3 秒）

### 5.4 GNSS 接入方式

GNSS 在融合系统中的三种接入范式（详见 [[GNSS数据管线]]）：

| 方式 | 接入点 | 约束形式 | 代表工程 |
|------|--------|---------|---------|
| **松耦合** | 位姿级 | 将 GNSS 解算的 ENU 位置作为 PriorFactor 注入因子图/滤波器 | LIO-SAM + GPS, VINS-Fusion |
| **紧耦合** | 观测级 | 将 GNSS 伪距/载波相位作为原始观测残差 | IC-GVINS, OB_GINS |
| **离线批优化** | 后处理级 | 整段轨迹 + GNSS epoch 做批量 BA | [[方法-GNSS-IMU 离线批优化]] |

对于从零搭建，推荐先实现**松耦合 GNSS**（维护成本最低）：
- 将 GNSS 经纬高转为 ENU
- 补偿 GNSS 天线到 IMU 的杆臂
- 添加 `PriorFactor<Pose3>` 到因子图
- 噪声模型：水平 0.5-2m (根据 HDOP)，垂直 2-5m

```pseudo
def add_gnss_factor(graph, gnss_msg, current_key):
    # WGS84 → ENU
    enu_pose = wgs84_to_enu(gnss_msg.lat, gnss_msg.lon, gnss_msg.alt)
    # 补偿杆臂 (GNSS 天线在 body 系的位置)
    T_w_gnss = enu_pose * T_body_gnss
    
    # 协方差：水平精度 > 垂直精度
    xy_noise = gnss_msg.horizontal_accuracy  # m
    z_noise = gnss_msg.vertical_accuracy     # m
    gnss_noise = noiseModel.Diagonal.Sigmas([
        xy_noise, xy_noise, z_noise,  # 位置
        100, 100, 100])                # 姿态（无约束）
    
    graph.add(PriorFactor_Pose3(X(current_key), T_w_gnss, gnss_noise))
```

## 6. 退化与故障

多传感器系统的鲁棒性不在于每个传感器都完美，而在于某个传感器出问题时，系统能优雅降级。

### 6.1 退化检测的三种级别

详见 [[方法-退化检测与修复]]、[[方法-6-DoF 退化检测]]、[[方法-SuperLoc退化检测实现]]。

| 级别 | 检测方法 | 触发器 | 修复策略 |
|------|---------|--------|---------|
| **特征级** | 点数统计 | LiDAR 角点 < 10 或面点 < 100 | 跳过当前帧，依赖 IMU 传播 |
| **自由度级** | Hessian 特征值 | `eig(H) < threshold` | 退化方向位移投影为 0，非退化方向正常更新 |
| **系统级** | 速度/偏置异常 | `|v| > 30 m/s` 或 `|bias| > 0.1` | 重置预积分，触发重定位 |

**6-DoF 退化检测的实现**（`raw/codes/LVI-SAM/src/lidar_odometry/mapOptmization.cpp:L1221-L1249`）：

```pseudo
def check_6dof_degeneracy(H):
    eigen_vals, eigen_vecs = eigen_decompose(H)
    degenerate_dims = []
    thresholds = [100] * 6  # 每个自由度的阈值
    
    for i in reversed(range(6)):  # 从最小特征值开始
        if eigen_vals[i] < thresholds[i]:
            degenerate_dims.append(i)
        else:
            break
    
    if degenerate_dims:
        # 构造投影矩阵，抑制退化方向的增量
        P = eigen_vecs.inv() * mask_degenerate(eigen_vecs, degenerate_dims)
        dx = P * dx  # 退化方向增量为零
        return DEGRADED, degenerate_dims
    
    return HEALTHY, []
```

### 6.2 传感器故障检测与子系统切换

详见 [[方法-多传感器冗余切换]]。

**LiDAR 健康监测**：
- 特征点数量 < 阈值 → 跳过扫描匹配
- Hessian 特征值检测 → 退化方向投影
- IMU pitch 角 > 1.4 rad → 禁用 IMU Slerp 融合 (过顶奇点)

**视觉健康监测**：
- 特征跟踪数 < 阈值 → 触发 `failureDetection()`
- VINS 重启：`clearState()` 全量重置 → 等待重新初始化
- `odomResetId` 递增通知 LIO 侧重置

**位姿初猜的优先级决策树**：

```
             ┌─ VINS 可用? ── YES ── [VINS 增量位姿初猜]
系统运行中 ──┤
             └─ VINS 不可用 ── IMU 可用? ── YES ── [IMU 角增量初猜]
                                          └─ NO  ── [保持上一帧位姿]
```

### 6.3 子系统切换的状态管理

切换时最关键的是状态一致性：

```pseudo
class FusionOrchestrator:
    def __init__(self):
        self.mode = LVIO     # 当前模式
        self.state = State() # 统一状态 (位姿、速度、bias)
    
    def step(self, sensors):
        # 1. 健康检测
        lidar_health = check_lidar_health(sensors.lidar)
        vis_health = check_vis_health(sensors.visual)
        
        # 2. 模式决策
        if lidar_health == HEALTHY and vis_health == HEALTHY:
            new_mode = LVIO
        elif lidar_health == HEALTHY:
            new_mode = LIO
        elif vis_health == HEALTHY:
            new_mode = VIO
        else:
            new_mode = IMU_ONLY  # 短暂维持
        
        # 3. 模式切换
        if new_mode != self.mode:
            log_warning(f"Mode switch: {self.mode} → {new_mode}")
            if new_mode == LIO and self.mode == VIO:
                # VIO→LIO: 保留当前的 bias 和位姿，丢弃视觉路标
                pass
            elif new_mode == VIO and self.mode == LIO:
                # LIO→VIO: VIO 需要用 LIO 的位姿重新初始化
                vis_odom.reinitialize(self.state.pose, self.state.bias)
            self.mode = new_mode
        
        # 4. 按模式调用对应前端 + 后端
        return self.estimators[self.mode].process(sensors)
```

```pseudo
    elif config.backend == "Ceres":
        backend = SlidingWindowBackend(config.window_size)
    
    # 健康监测
    health_monitor = SensorHealthMonitor(config.health_params)
    
    # ---- Phase 4: 静止初始化 ----
    state = initialization.standstill_init(imu_queue)
    # 估计初始重力方向、加速度计和陀螺仪偏置
    # 若静止检测失败，降级至动态初始化
    if not state.valid:
        state = initialization.dynamic_init(sensors)
    
    # ---- Phase 5: 进入主循环 ----
    main_loop(sensors, scheduler, backend, health_monitor, state)
```

### 7.2 主循环

```pseudo
def main_loop(sensors, scheduler, backend, health, state):
    while ros_ok():
        # 1. 传感器调度 → 生成测量窗口
        window = scheduler.collect_window()
        if not window.complete:
            continue
        
        # 2. 传感器健康检测
        health_diag = health.check_all(window, state)
        
        # 3. 前端：特征提取 / ICP 匹配 / IMU 预积分
        lidar_factors = []
        visual_factors = []
        
        if health_diag.lidar_healthy:
            lidar_factors = lidar_frontend.process(window.lidar, state)
        
        if health_diag.visual_healthy:
            visual_factors = visual_frontend.process(window.camera, state)
        
        imu_factors = imu_preintegrator.process(window.imus, state)
        
        # 4. GNSS 因子（如果有新 fix）
        gnss_factors = []
        if window.gnss and health_diag.gnss_healthy:
            gnss_factors = gnss_processor.process(window.gnss, state)
        
        # 5. 构建因子图并优化
        backend.add_factors(imu_factors + lidar_factors + 
                           visual_factors + gnss_factors)
        state = backend.optimize()
        
        # 6. 退化降级处理
        if health_diag.mode_changed:
            backend.handle_mode_switch(health_diag.new_mode, state)
        
        # 7. 发布结果
        publish_odometry(state.pose, state.velocity)
        publish_tf(state.pose)
        publish_diagnostics(health_diag)
        
        # 8. 关键帧判断 → 触发回环
        if is_keyframe(state, window):
            loop_factors = loop_detector.detect_and_verify(state, window)
            if loop_factors:
                backend.add_factors(loop_factors)
```
